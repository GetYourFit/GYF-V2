# F2.5 search/facets bounded-latency slice — 2026-07-25

This slice adds rollback-safe observability, bounded database budgets, and a durable searchable-catalogue truth snapshot. It does **not** close or promote global F2.5; production India-vantage samples and read-only `EXPLAIN (ANALYZE, BUFFERS)` remain required.

## Changes

- Catalogue request access logs retain the existing sanitized `X-Request-ID` and now include fixed-label catalogue stage totals/outcomes and total wall time for `/items/*`. No query text, authorization token, user profile, or item payload is logged. Pure ASGI request context preserves stage timings across FastAPI execution.
- Search responses expose `X-GYF-Search-Mode: semantic|lexical` without changing the JSON contract. Encoder failure remains an honest lexical fallback; database exceptions remain errors.
- Search SQL uses `GYF_CATALOG_SEARCH_STATEMENT_TIMEOUT_MS` (default 2500 ms, bounded 250–10000) via transaction-local `set_config`. Facets uses `GYF_CATALOG_FACETS_STATEMENT_TIMEOUT_MS` (default 1500 ms, bounded 250–10000). PostgreSQL cancellation propagates and the connection transaction rolls back through the pool context; no empty-success masking is added.
- Existing query-embedding cache key remains normalized query + model ID. No result cache was added without production plans/catalogue-version evidence; filters therefore cannot share an unsafe result cache.
- Completed ingest now refreshes one durable `catalogue_truth_snapshots` row whose predicate exactly matches Explore browse/search eligibility: available, supported category, positive price, embedding present, usable HTTPS image, adult audience, and no taxonomy quarantine. The prior row is retained if refresh fails, and `/items/facets` returns `503 catalogue truth is refreshing` until the first successful snapshot exists instead of inventing an empty catalogue.
- Ingestion now quarantines adult/kids conflicts and feed-supplied invalid image URL, HTTP status, content type, or size facts without fetching remote images in-band. Browse/search rows always carry a usable HTTPS `image_url` plus `image_status="usable"`, while the shared Expo inaccessible-image fallback/retry remains unchanged.
- Facets are now a versioned, cacheable snapshot with `ETag: "catalogue-<version>"`, age/freshness, last successful ingest timestamp, and bounded category/audience/source/image-status counts. Region requests still fall back to the global region-neutral scope when no region-specific rows exist.

## Rollback

Set the two timeout settings to a measured higher value only as an incident mitigation, or revert the API release to the previous verified SHA. The search-mode header, snapshot metadata, and access-log fields are additive. Do not disable error propagation or convert cancellation to an empty result. Preserve the prior good snapshot on refresh failure. No source cutover, Cuelinks campaign-only policy, audience broadening, or topology change landed here.
