# F2.5 search/facets bounded-latency slice — 2026-07-25

This slice adds rollback-safe observability and database budgets only. It does **not** close or promote global F2.5; production India-vantage samples and read-only `EXPLAIN (ANALYZE, BUFFERS)` remain required.

## Changes

- Catalogue request access logs retain the existing sanitized `X-Request-ID` and now include fixed-label catalogue stage totals/outcomes and total wall time for `/items/*`. No query text, authorization token, user profile, or item payload is logged. Pure ASGI request context preserves stage timings across FastAPI execution.
- Search responses expose `X-GYF-Search-Mode: semantic|lexical` without changing the JSON contract. Encoder failure remains an honest lexical fallback; database exceptions remain errors.
- Search SQL uses `GYF_CATALOG_SEARCH_STATEMENT_TIMEOUT_MS` (default 2500 ms, bounded 250–10000) via transaction-local `set_config`. Facets uses `GYF_CATALOG_FACETS_STATEMENT_TIMEOUT_MS` (default 1500 ms, bounded 250–10000). PostgreSQL cancellation propagates and the connection transaction rolls back through the pool context; no empty-success masking is added.
- Existing query-embedding cache key remains normalized query + model ID. No result cache was added without production plans/catalogue-version evidence; filters therefore cannot share an unsafe result cache.

## Rollback

Set the two timeout settings to a measured higher value only as an incident mitigation, or revert the API release to the previous verified SHA. The search-mode header and access-log fields are additive. Do not disable error propagation or convert cancellation to an empty result. No source, Cuelinks path, audience policy, topology, or database migration changed.
