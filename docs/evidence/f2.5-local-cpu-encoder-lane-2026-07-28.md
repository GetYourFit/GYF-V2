# F2.5 local CPU SigLIP2 lane — implementation plan

Status: **local evidence only; F2.5 remains HOLD**. No provider, production binding,
registry lane, vector index, or production environment will change in this packet.

## Plan before implementation

1. **Trace and preserve the boundary.** Keep `ImageTextEncoder`, the registry-selected
   `google-siglip2-base-v1`, and 768-dimensional normalized vectors unchanged. Verify
   `encoder_for()` selects explicit `local_cpu` even when a stale remote URL exists;
   keep API callers behind `CachedTextEmbedder` and preserve keyword fallback.
2. **Make the local path bounded, not clever.** Audit the lazy `SiglipEncoder` for safe
   CPU/MPS/CUDA/XPU selection, validate finite/unit vectors and 768 width, cap batch size
   and CPU thread resources, and avoid unbounded local work in the API search request.
   Do not add ONNX/OpenVINO or a vendor/runtime dependency without parity evidence.
3. **Add only regression coverage for the root cause.** Test invalid batch/resource values,
   device safety and honest failure/fallback behavior; test that the canonical factory and
   existing lexical path remain unchanged. Do not fabricate semantic success on encoder
   failure or return empty results as a substitute for a failed truth query.
4. **Add a repeatable no-provider benchmark.** Run a bounded fixed query set from
   `ml/tests/fixtures/encoder_foundation.json` (plus representative catalogue terms), one
   cold load and repeated warm text batches. Record exact model URI/version, dependency
   versions, device/thread settings, vector dimension/norm, p50/p95, RSS, failure behavior,
   and cache-hit behavior. Skip honestly if model weights/dependencies cannot be fetched.
5. **Decide against the existing gate.** Compare local results with the fixed India targets
   (uncached p50 <=1.5s/p95 <=3s; cached p50 <=0.4s/p95 <=0.9s) without calling local tests
   production evidence. A local lane can be recommended HOLD/GO for shadow only; F2.5
   requires sustained India-vantage HTTP-200 evidence and production `EXPLAIN (ANALYZE,
   BUFFERS)`, per `docs/deploy/gpu-lane.md`, `docs/plans/scale-3k-inr.md`, and the active
   execution contract.

## Hardware/resource constraints validated

- The repository's current supported auto order is CUDA → Intel XPU → CPU; Apple MPS is
  deliberately excluded after an isolated real-forward numeric probe. Explicit `local_cpu`
  must remain CPU, not auto-device behavior.
- Render is the always-on CPU target. The existing API image may be torch-free, so the local
  encoder is lazy and must not make startup fail; missing ML dependencies must leave search on
  the existing indexed lexical fallback.
- Existing docs require bounded batches, RSS/cold/warm evidence, artifact/licence registry
  identity, no production reindex, no paid provider, and no provider/config cutover here.
- Existing query cache is keyed by normalized query + model ID and lexical fallback is
  already truthfully labelled; neither will be bypassed or weakened.

## Implementation and benchmark evidence

The local lane already had the correct port/factory/registry wiring, API cache, bounded HTTP
remote timeout, and lexical fallback. The smallest justified code change was therefore limited
to local safety and repeatability:

- `SiglipEncoder` now rejects explicit MPS and unavailable explicit accelerators, caps configured
  CPU threads and image/text batch work, refuses a detectable container/address-space memory limit
  below the configured 4,000,000,000-byte floor, and rejects non-finite/non-unit/wrong-width output.
- ML settings validate batch size, I/O workers, CPU threads and the memory floor. No Render value,
  production environment, provider, model registry lane, or vector index changed.
- `ml/eval/benchmark_encoder.py` is a repeatable bounded CLI. It is pinned to the registry's
  production `google-siglip2-base-v1` URI and records model licence/lane, exact query set,
  device/runtime/thread/RSS/dimension/norm data, cold and warm p50/p95, and truthful failure
  status. It never writes catalogue rows.
- Regression tests cover MPS refusal, invalid batch size, memory refusal, factory selection,
  output shape/norm and remote/local failure fallback. The API's `_embed_or_none` lexical path
  remains unchanged and still labels `X-GYF-Search-Mode: lexical` on encoder failure.

### Exact commands and results

Baseline of the existing lane before this packet (same registry URI, local CPU, two Torch
threads, representative eight-query batch):

```bash
GYF_PERCEPTION_DEVICE=cpu OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  /opt/homebrew/bin/uv run --project ml --extra perception python - <<'PY'
import json, resource, time
from pathlib import Path
import numpy as np
from gyf_contracts.eval_report import RUNTIME_MODELS
from perception.model import SiglipEncoder
fixture = json.loads(Path("ml/tests/fixtures/encoder_foundation.json").read_text())
texts = [q["text"] for q in fixture["queries"]] + [
    "black formal kurta", "women cotton trousers", "blue running shoes",
    "linen summer outfit", "festive saree", "casual denim jacket",
]
encoder = SiglipEncoder(RUNTIME_MODELS["encoder"].model_uri, device="cpu")
started = time.perf_counter(); vectors = encoder.encode_texts(texts)
cold = time.perf_counter() - started
warm = []
for _ in range(5):
    started = time.perf_counter(); encoder.encode_texts(texts)
    warm.append(time.perf_counter() - started)
rss = resource.getrusage(resource.RUSAGE_SELF).ru_maxrss
rss = int(rss if rss > 10_000_000 else rss * 1024)
assert vectors.shape == (len(texts), 768)
assert np.isfinite(vectors).all()
assert np.allclose(np.linalg.norm(vectors, axis=1), 1.0, atol=1e-3)
print({"cold_seconds": cold, "warm_seconds": warm, "rss_bytes": rss})
PY
```

The cold run downloaded weights and took **131.635 s**; a fresh cached process then took **8.863 s**
to first encode. Existing warm batch p50 was **0.090 s** and p95 **0.093 s** for eight queries;
RSS peak was **3,990,372,352 bytes** on the network-cold process and **3,387,146,240 bytes** on
the cached process. These are workstation measurements, not Render or India evidence.

Repeatable post-change command (weights were cached for this run):

```bash
GYF_PERCEPTION_DEVICE=cpu OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  /opt/homebrew/bin/uv run --project ml --extra perception \
  python -m eval.benchmark_encoder --device cpu --repeats 3 \
  --timeout-seconds 300 \
  --output docs/evidence/results/local-cpu-siglip2-2026-07-28.json
```

The fixed bounded set is eight queries: `red summer dress`, `linen shirt`, `black formal kurta`,
`women cotton trousers`, `blue running shoes`, `linen summer outfit`, `festive saree`, and
`casual denim jacket`. Post-change output is committed at the JSON path above:

- model `hf-hub:timm/ViT-B-16-SigLIP2`, version `google-siglip2-base-v1`, Apache-2.0,
  registry lane `production`, 768 dimensions;
- macOS arm64, Python 3.12.13, Torch 2.12.1, CPU selected explicitly, 10 logical CPUs,
  Torch intra-op 2 and inter-op 1;
- cold first-query wall time **10.118 s** (cached weights), warm single-query p50
  **20.09 ms**, p95 **25.94 ms**, max **26.20 ms**;
- every vector finite, 768-dimensional and unit norm in `[0.99999994, 0.99999994]`;
- peak RSS **3,386,425,344 bytes**; no cgroup limit was detectable;
- the API Postgres query cache was not exercised by this no-database benchmark. Its existing
  normalized-query + model-ID key and cache-hit tests remain the cache evidence.

A failed load/deadline is reported as `status: failed` and a nonzero exit, never as an empty or
semantic-success result. The API catches encoder failures and uses the bounded PostgreSQL lexical
fallback; no semantic confidence is fabricated.

## Decision against current F2.5 targets

**Recommendation: HOLD for the local CPU serving lane; GO for continued local shadow/benchmark
work only.** Warm single-query compute is comfortably below the 1.5 s p50 / 3 s p95 uncached
India target on this workstation, but the measured cold load is 10.118 s and peak RSS is about
3.39 GB. That memory footprint is not established as safe on Render Starter, and this run has no
India network/HTTP, production `EXPLAIN (ANALYZE, BUFFERS)`, sustained HTTP-200, catalogue-truth,
cache-hit, or reliability evidence. The 4 GB preflight therefore fails closed on a constrained
container and preserves lexical search rather than risking an OOM or false semantic success.

No paid provider is recommended from this local evidence. If the owner later approves a provider
experiment after the local lane's Render-compatible memory/latency gate fails, the minimum class
is a scale-to-zero CPU text-inference endpoint with pinned registry artifact, bearer auth, bounded
cold/warm timeout, RSS/CPU evidence and cost-per-success under the existing ₹3,000 envelope—not a
production cutover by this packet.

F2.5 remains **HOLD**. It can close only with the active contract's sustained India-vantage
catalogue SLOs, all HTTP 200s, production `EXPLAIN (ANALYZE, BUFFERS)`, truthful semantic/lexical
mode evidence, and rollback proof. No local test or this benchmark promotes production.
